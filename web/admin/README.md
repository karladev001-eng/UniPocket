# Uni Pocket 管理画面

この入口は一般アプリと別originで配信する管理Worker用です。`/api/admin/me`で管理者を確認してからデータを取得します。認証切れや通信失敗では編集中の入力を画面に保持し、利用者の操作で別タブのログインと認証再確認へ進みます。編集中の内容や回答を端末ストレージへ保存しません。

`web`で実行します。

```sh
npm run typecheck:admin
npm run test:admin
npm run build:admin
```

出力は`web/dist-admin`です。公開用の`build`とは分かれており、一般アプリのアセットは取り込みません。管理画面にはオフライン機能を作りません。管理Workerで全パスのAccess保護、JWT検証、private/no-storeヘッダーとCSPを適用する必要があります。

ローカルの製品確認は管理APIを`127.0.0.1:8788`で起動し、`npm run dev:admin`（`127.0.0.1:5174`）を使います。ViteのAPI proxyだけでは管理者認証は通りません。バックエンドのfail-closed認証を維持したまま、テスト用署名・所有者設定を備えた環境で確認します。本番用の認証回避スイッチはありません。

日付の編集は日本時間、APIはUTC ISO8601、日次集計キーは日本時間の日付です。公開済みアンケートの設問は編集せず、複製時に設問・選択肢をすべて新IDにします。CSVは管理APIから別操作で取得し、画面側で回答や集計を捏造しません。

記事は題名・投稿者・カテゴリの検索語と公開状態をサーバーに送り、通報も確認状態をサーバーで絞り込みます。50件ずつcursorで追加取得し、古い検索応答は表示へ反映しません。通報対象は一覧へ読み込まれている範囲に依存せず単体取得します。非表示・再公開は確認した対象ID・revision・理由と同じIdempotency-Keyで再試行します。

単体テストは認証の境界、入力保持・重複再試行、日時・期間・設問制約、DOMのテキスト出力と表の意味を検証します。実ブラウザの寸法・キーボード・Cloudflare Access・実D1の検証は統合時に別途必要です。

運営記事は「記事」の「＋ 運営記事」から登録します。固定の `Uni Pocket運営` と文字付き盾バッジを表示し、プレビューとログイン不要の公開確認後に即時公開します。カテゴリ・講義ID・公式埋め込みコードは任意欄にまとめています。Notion本文や公開状態はNotion側で管理します。認証・通信失敗では確認済みの送信内容と冪等キーを画面内に保持します。「前回の送信結果を確認」は保持した前回の内容をプレビューして同じ内容だけを再送する復旧操作です。結果の確認後は、保持した現在の入力と保存結果を比較します。新しい変更の反映は別のプレビュー確認を必要とします。確定的なURL重複拒否では前回の送信を解除し、URL修正後に新しい内容を確認できます。競合は最新版と比較し、明示した適用操作だけで編集した項目を引き継ぎます。画面を閉じると下書きは残りません。

`0004_admin_authors.sql` は既存プロフィールと記事を通常投稿のまま保ち、独立したランダムIDの運営プロフィールとサーバー専用の著者種別を追加します。運営プロフィールへの匿名セッション発行・更新と記事の著者変更はDBでも拒否します。公開APIは `authorKind: user | admin` を追加し、種別の欠落・未知値はバッジなしで表示します。管理API `POST /api/admin/articles` と `PATCH /api/admin/articles/:id` は毎回Access認証・Origin・永続レート制限を適用し、必須の `Idempotency-Key`、編集時の `revision` を検証します。成功監査と変更は同じD1 batchです。運営名義の正規化URL重複は409 `duplicate_article` と既存ID/一般アプリ内パスを返し、管理画面から既存記事詳細を確認できます。編集は運営記事のみで、非表示状態を変えません。

ローカルWorkerの初回起動前とCA/実行系更新後は`npm run verify:tls`を実行します（ルートREADME参照）。合成データだけの実ブラウザ確認は、両方をビルドした後に `node tests/helpers/public-admin-qa.mjs` を実行します。loopbackの8890/8891で使い捨てD1・テスト署名付きの一般/管理画面を提供し、長い題名の架空運営記事も生成します。署名鍵やテストルートは本番Workerに入りません。`node --test tests/server-admin-author-runtime.mjs` は認可・偽装・並行再送・正規化URL重複・revision競合・監査失敗時の原子性を実D1で確認します。本機能の配信、リモートDB migration、実記事投稿、Notion公開は別途の明示承認が必要です。
