## 本人の決定と目的

「とりあえず、静岡大学浜松キャンパス版で進める間はアプリ側で用意するようにしましょう。」

浜松キャンパス版では年間行事予定をアプリ側で用意する。学生が持ち込む資料は自分の履修登録PDFだけ。科目・曜日・時限・教室の読取り候補を確認し、アプリの授業期間・祝日・休業・例外日程と組み合わせた結果を確認して登録する。v1の『学生が2つのPDFを取り込む』流れを置き換える。

## 対象内外と入出力

対象は固定サンプルによる登録モックと、ホーム/時間割の登録案内。学生側の入力は履修登録PDFの読取り候補の修正・カレンダーでの曜日時限指定・教室・本人確認。アプリ側の日程の大学/キャンパス/年度/日付/扱いは読取り専用。出力は日付ごとの通常/除外/例外・理由・登録件数・完了見本。

対象外は実PDF解析/OCR、実際の公式日程データの作成・公開、SwiftUI製品への組込み、外部通信、実データ保存、更新配信。公式リンクは原資料の案内であり、モックの架空日程が公式確認済みとは扱わない。確認日・版も見本として明示する。学生に年間行事予定表の提出・読み取り失敗の修正を求めない。

## 仕様と番号付き受入条件

- I1 / AC1: 「あなたが用意する履修登録PDF」と「アプリが用意する浜松キャンパスの日程」を区別。アプリ日程に対象大学・キャンパス・年度・確認日/版の見本・公式資料へのリンクを示す。アプリ日程は利用者が書き換えられない。
- I2 / AC2: 学生が科目の曜日/時限をカレンダーのマスで指定し、教室・PDF読取り候補を修正できる。履修PDFの大学/キャンパス/年度をアプリ日程と照合。不一致なら学生側の読取り訂正か正しい年度のPDFサンプル再選択へ案内し、アプリ側の年度を変更して合わせない。
- I3 / AC3: アプリ側で確認済みとした日程サンプルを適用。授業期間・祝日・休業・明示例外の結果を日付単位で表示し、科目は保持、除外理由の重複を二重減算しない。標準フローで日程の全項目を学生に再判定させない。
- I4 / AC4: アプリ日程未確認/更新待ちでは登録確定不可。本人確認だけで回避できず、年間PDFの提出も要求しない。確認済み日程の表示例へ切替える導線を示す。講義候補を修正したら本人確認を無効化し、プレビューを再計算する。完了はページ内の見本であり既存画面を実更新したと称さない。

## 製品としての方針

- 共通日程は運営側が大学の公式資料を確認して用意し、対象年度・キャンパス・確認日・版・出典を管理する。最初は浜松キャンパスだけを対象とする。
- 確認済みの日程を端末に保存し、オフラインでも同じ時間割を表示する。モックでは永続保存の実装は行わない。
- 臨時休講・個別の教室変更・振替は自分の時間割の調整として別に扱う。共通日程の更新で個人調整を無断で上書きしない。
- 不明な試験期間や授業日の扱いを自動推測して公開しない。共通日程の未確認事項は運営側で解決し、確認済みの日程を提供する。
- 全国対応や未対応大学向けの年間PDF取込みは今回の対象外。将来の拡張として検討する。
