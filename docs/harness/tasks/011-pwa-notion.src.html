今回の移行

Android・iPhone・PCで開けるPWAを新設します。ホーム / 時間割 / 記事 / メモ / その他の5タブ。掲示板の入口は出しません。

記事を探す → Notionをアプリ内で読む → 保存する → 投稿者の記事を見る。登録は公開URLとタイトルが中心です。メール登録なしで、このブラウザの匿名ユーザーとして利用します。

構成案：Cloudflare Static AssetsでPWA配布、WorkersでAPIと匿名セッション、D1で共有記事を保存。個人データは端末内。順序：表示検証とPWA基盤 → 個人機能の移植 → 記事と集計 → 実端末と配布確認。

初回提案：外部カレンダー連携は初回なし（確定）。PWAは新規データで開始（確定）。旧版は未運用のため、仮データの移送は行いません。公開先・認証設定は未提供です。

仕様と画面

項目を開くと画面を確認できます。

Swift版を残し、掲示板のない5タブをPWAとして配布する。

個人機能は端末内保存。Notion本文・共有集計は通信が必要。外部カレンダー連携は初回対象外。旧Swiftデータの移送も対象外。PWAは新規データで開始します。

既存Swiftコードを保持し、独立したWebアプリを追加する。

公開URLを登録し、プレビューしてから記事を共有する。

不正URLは入力欄で案内し、通信失敗時は入力を保持。必要時は公式の埋め込みコードからURLのみ取り出す補助操作を用意します。

Notion本文をアプリ内で読み、ブックマークする。

Notion公式の埋め込みを使用。公開解除などに備え「Notionで開く」を常設。閲覧数はアプリ詳細を開いた記録で、本文読了やNotionのPVではありません。

投稿者名から、そのユーザーの記事一覧へ進める。

Cloudflare Workers＋D1で数を管理し、同じ操作を重複集計しない。

ブックマークの数は現在保存している匿名ユーザーIDの数です。実人数とは限りません。閲覧は同一利用者・記事・日につき1回の提案。匿名の別端末までの同一性は保証しません。

新しいバージョンを同じURLへ配信し、保存してから更新する。

配信後、起動・オンライン復帰・手動確認で検出します。アプリを閉じた端末への即時更新やOSのプッシュ通知は初回対象外。通信失敗時は旧版を維持します。

検証から配信までの手順と、問題があった場合に戻す手順を用意する。

空・通信失敗・匿名ユーザーの準備失敗でも、次の操作がわかる。

読込中の状態を案内する。

保存なしの状態を案内する。

オフラインの状態を案内する。

取得失敗の状態を案内する。

匿名ユーザー準備失敗の状態を案内する。

Swift版と保存データを保持し、外部カレンダー連携は初回対象外とする。

App Store / Play Store配信、掲示板、アプリ内記事執筆、Notion独自ドメインは初回対象外です。
