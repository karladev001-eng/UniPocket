UNI POCKET · PLAN 020 / v2 · 実装承認待ち

020 · URLから、みんなのUni Pocketへ。

目的と本人の回答URLを知っている人ならインストールできるようにしたい。また、管理者用の管理システムも作りたい。記事関連の管理やアンケートやお知らせの配信、アナリティクスなど。

本人の回答は「記事は登録後すぐ公開し、管理者が後から非表示」「お知らせ・アンケートはまずアプリ内だけ」。一般アカウントなし、端末の予定・メモは端末内を継承する。v2の回答は「ユーザーからデータを送信することはせず、ダウンロード数の推移や、記事の閲覧数などだけでいいです。あとは、アンケート結果など。」で、追加の利用状況送信を削除した。

予定はそのまま。情報の入口と、運営の道具を加える。

一般の人は共有URLからアプリを開き、端末の操作でホーム画面に追加する。管理者は別URLで本人確認し、記事・お知らせ・アンケート・集計を扱う。既存のアプリoriginと共有D1を維持する案を優先する。

利用者

URL → アプリを開く → 必要ならホーム画面へ追加。予定の下の1行からお知らせを読み、任意でアンケートへ回答する。下部5タブは継続。

管理者

別URL → Cloudflare Access＋サーバー側JWT検証 → 5区画の運営画面。記事の非表示、下書きから配信、回答集計へ進む。

守るもの

既存の匿名ID、記事・ブックマーク、端末の予定・メモ・背景。新しい一般ログインや通知許可は不要。投稿直後の公開を継続。

対象外

プッシュ/メール、事前記事審査、複数管理者、課金、Notion本文編集、予定/メモの運営閲覧、正確な実人数・インストール総数。

1　管理の境界を先につくる

管理Worker/Access/JWT、追記migration、監査・競合検出。

2　ローカルと保護previewで試す

記事管理、配信と回答、集計、代表状態と狭幅を検証。

3　既存データと認可を確認する

同origin/D1を保持。一般利用者・偽造/期限切れ管理者の拒否を確認。

4　具体的な公開対象を最終確認する

URLと公開記事を提示。最終確認後に一般対象のAccessだけ切り替える。

操作モックを開く ↗ 提案・架空データ / 通信・実配信なし

仕様の正本は 020-public-admin.md / v2。このHTMLの回答・コメント・コピーはCodexへ送信されず、承認を記録しない。未解決事項0件と実装承認は別。現在は仕様・モックの準備段階。

提案仕様

5つの項目を開くと、画面・規則・構成まで確認できます。本文中の画面はすべて提案です。

URLから一般利用し、管理は別の本人確認で守る。

アプリ内だけで届き、既存5タブを増やさない。

同じoriginとD1を維持し、URL共有と追加手順を用意する。

既存IndexedDB・匿名セッション・背景・予定・メモとD1のID/データを保持する。新しい公開用DBへ無断で切り替えない。URLは転送可能で、知らない第三者も到達し得る。noindexは検索掲載の抑制であり認可ではない。

旧iPhoneは、一般対象のAccess切替後に更新ファイルを取得して復旧する可能性がある。Mac接続を必須と断定せず、同じPWAで実際の更新適用を確認する。公開や新規追加だけで復旧完了と報告しない。

管理HTML・API・集計・CSVを、AccessとJWTで二重に検証する。

管理Assets全体をAccessで保護し、サーバーでも署名・issuer・audience・有効期限・所有者1名の許可を検証する。匿名プロフィール名・HTTPメールヘッダー・画面のroleを認可に使わない。静的Assetsの内部routerでctx.accessが渡らない点を考慮しJWT検証を使う。

管理画面はprivate/no-store、SW/オフラインキャッシュなし。編集中の認証切れは入力を保持し、再ログインへ案内する。無条件reloadで入力を捨てない。一般APIに管理操作の迂回経路をつくらない。Cloudflareアカウント全体のAccessを解除せず、最終承認された一般Worker/URLに対する対象だけを切り替える。

管理者は5区画から、確認が必要な情報へすぐ進める。

概要／記事／お知らせ／アンケート／集計。PCはサイドナビ、スマホは横幅を抑えた上部ナビ。日付と期間は日本時間を使う。

記事はすぐ公開し、運営が理由付きで非表示・再公開する。

対象・理由を確認して非表示にし、元の記事と件数を残す。

作者になりすます、記事本文を書き換える、恒久削除や一括削除は行わない。作者は運営の非表示を解除できず、作者が削除した記事を管理者が復活させない。

通報は重複を抑え、非表示を公開の全経路へ反映する。

不適切／誤情報／リンク不備／その他と補足500文字。匿名セッションごとに同一記事の未処理通報を重複作成せず、管理者は確認済みにできる。

非表示は人気・新着・検索・投稿者・ブックマーク・公開詳細APIから除外し、閲覧/ブックマーク書込みも拒否する。作者専用の自分の投稿管理では状態と理由を表示。前面復帰・再取得で古いカードを除き、通信不能時はキャッシュしたNotion埋込みを新しく開かない。すでに表示した本文や元Notionページの遠隔消去は保証しない。

下書きとプレビューから、アプリ内でお知らせと回答を届ける。

開始・終了と版で表示を決め、開いたものだけ既読にする。

利用者の表示と配信期間を確認してから公開する。

期限判定はジョブ遅延に依存しない。公開済みの本文変更は改訂版として確認し、端末の既読は版ごと。二重送信・失敗再試行で重複作成しない。

ホームのベルと予定の下の1行、その他から一覧へ。開いたお知らせの版だけ端末内で既読にし、既読情報は送信しない。0件・期限切れ・失敗・オフラインを区別し、お知らせ取得に失敗しても予定・メモを使える。

3形式・最大10問で任意回答し、失敗しても入力を失わない。

管理者は題名・紹介・開始・締切、単一選択／複数選択／自由記述を下書きで作る。選択肢最大10、自由記述1000文字。プレビューと確認後に公開。公開後の設問・選択肢は固定し、複製して新しい版にする。題名・紹介・締切は確認して変更可。

同じ匿名ユーザーIDで1回答、再送も同じ結果にする。別ブラウザとの同一人物判定や「1人1回」は保証しない。管理者のみ選択集計・回答数・匿名自由記述とCSVを確認でき、一般APIから他の回答・全回答を取得できない。

入力 → 送信中必須項目を確認し、送信中は二重操作を抑える。
成功 / 回答済み受付結果を示し、同じIDの再送で二重計上しない。
通信失敗入力を保持。接続後の再送を用意。
送信時に締切サーバー判定で拒否。受付終了を知らせ、入力を残す。

操作モックの回答画面で送信結果と入力保持を切り替えられる。

記事の閲覧推移と現在の保存数、アンケート結果を確認する。

日次の集計と期間・定義を示し、未収集と取得失敗を分ける。

7日／30日／最大90日の任意期間、日本時間。記事の日別/期間内閲覧・現在のブックマーク・アンケート回答数を表示する。現在のブックマークは集計時点の値。閲覧の定義・重複除去と人気記事の直近7日スコアは019を継承し、累計閲覧とは分ける。

日次集計は日付・コンテンツID・件数・確定時刻のみで利用者IDを持たず、明細の期限前に確定する。回答は受付日時で日別に計上。復元できない過去は未収集にする。CSVは日付・対象ID/題名・件数・集計時刻のみ。選択結果と匿名自由記述はアンケート結果へ進み、自由記述CSVは別操作。

追加の利用状況送信を設けず、お知らせ既読は端末内だけにする。

起動・画面種類/履歴・インストール/standaloneイベント・訪問者/ブラウザ数を収集せず、協力設定・usage送信API/テーブルも作らない。お知らせの開封送信・サーバー既読・開封数/率も対象外。匿名セッション、記事取得/閲覧・保存・投稿・通報、任意のアンケート回答など機能に必要な通信は残る。

予定・PDF・メモ・背景・検索文・URLクエリ・位置情報を収集せず、IP/端末指紋を集計へ保存しない。不正対策の既存rate limitは別用途。保持上限の提案：記事閲覧明細30日、終了アンケート個別回答は終了後90日、コンテンツ日次集計と管理監査365日。削除失敗は監視して再実行する。一般APIへ利用者別の行動履歴を出さない。

PWAのダウンロード/インストール推移は、技術的制約から初版対象外とするv2の提案（本人の確定判断ではない）。検知の対応環境が限られ、Androidの追加承諾でも完了を保証しないため、カード/グラフ/近似値は出さず、asset取得数も代用しない。将来は定義と対応環境を別途検討できる。web.dev: PWA detection、MDN: appinstalled event（2026-10-20確認）。

失敗と既存データを守り、確認を経て一般公開へ切り替える。

読込中見出しと処理状況を表示。空データと取り違えない。
0件 / 未収集0件は該当なし、未収集は記録なし。意味を分ける。
取得失敗 / オフライン共有情報に再試行。端末の予定・メモは利用可能。
認証切れ / 更新競合管理データを伏せ本人確認へ。409では入力を保持。

更新と監査を同時に成立させ、競合・連投・CSVを検証する。

入力上限・https検証・XSS防止・CSRF/Origin検証を行い、CSVは機密値を除き表計算式を無害化する。匿名IDとIPのrate limitを調整し、学内Wi-Fiで同じIPの100利用環境が初回起動しても通常利用を阻害せず、投稿/通報/回答の連投を抑える。無料枠から始め、有料へ自動変更しない。上限・障害時も端末内の予定・メモと安全な更新を保つ。

既存の一般Workerと端末ホームを拡張し、管理Workerを分ける。

匿名セッションと記事APIを継承し、私的な端末データを移さない。

管理用の構成と追記migrationを提案する。

保護previewで受入を満たし、公開URLと共有データを示して最終確認する。

  1. 320×640、390×700、PCで主要画面と代表状態、44px操作域・入力16px・キーボード・フォーカス・単一閉じる操作を確認。
  2. 実D1で非表示全経路、二重回答・締切・競合、日次集計と保持期限、CSV・監査を検証。
  3. 偽造・期限切れ・別audienceを拒否。一般URLの未認証利用と管理URLの未認証拒否を別々に確認。
  4. 既存共有記事を点検し、具体的な公開URL・管理URL・対象記事と保護確認を提示。最終確認後、承認された一般対象のAccessだけ切り替える。
現時点は仕様・モックのみ。Access解除、Cloudflare作成、D1 migration、実配信は行わない。旧iPhoneの復旧は同じPWAで別途実確認する。

公開originとD1を継承し、管理の認証とデータ公開範囲を分ける。

一般：既存Worker/ASSETS、匿名session、公開可視性のあるAPI。管理：別Worker/別origin、管理Assets全体Access、サーバーJWT認可、private/no-store。D1のみ共有する。

データ案：記事visibility/revision/理由・通報、お知らせと改訂版（既読は端末内）、アンケート/設問/選択肢/回答、記事/回答の日次集計、管理監査。通常の予定・メモDBをサーバーに移さない。

通知拡張・一般ログイン・Notion編集・複数管理者は初版の対象外。

プッシュ/メール、事前審査、学籍認証、課金/広告、外部カレンダー、Swift変更、私的な予定/メモの閲覧、ダウンロード/インストール推移、起動/画面/訪問者数の追加収集、お知らせ開封集計、正確な実人数、AI内容判定、恒久削除・大量一括操作も含めない。

全文は仕様正本 v2。以下は確認入口。

  1. AC1 一般公開：同origin/D1と端末データを維持。URL共有とOS追加手順、公開対象だけのAccess切替。S1 / 一般入口
  2. AC2 管理認証：全管理URLをAccess保護しJWT・所有者を検証。SWなし/private。S1 / 認証
  3. AC3 管理ホーム：5区画・PCサイドナビ・スマホ小型ナビ、概要から対象へ。S1 / 管理
  4. AC4 記事管理：検索、理由と確認で非表示/再公開、本文・著者・件数保持。S2 / 管理
  5. AC5 通報と可視性：未処理の重複防止、非表示の全公開経路/書込み拒否、作者には理由。S2 / 反映
  6. AC6 お知らせ配信：下書き・プレビュー・確認、予約/期限・改訂、入力保持と重複防止。S3 / 配信
  7. AC7 利用者の受信：小さなベル＋予定下1行、開いた版だけ既読。0件/失敗/期限/オフラインを区別。S1 / ホーム、S3 / 受信
  8. AC8 アンケート：3形式/最大10問、任意回答・二重計上防止・入力保持、管理集計とCSV。S3 / 回答

  12. AC12 公開切替：狭幅/実D1/認証/既存データを検証し、具体的な対象の最終確認後に切替。S5 / 受入

未解決事項

実装必須の未回答事項なし。記事の即時公開とアプリ内配信は本人回答済み。管理者1名、同origin/既存D1、最大設問数、保持期限、コンテンツ日次集計などはこの版の具体的な提案であり、既存の本人決定とは扱わない。コメントで改訂できる。

仕様への回答と実装承認は別。公開切替時は実際のURL・対象共有記事・管理画面の保護結果を具体的に提示して最終確認する。
