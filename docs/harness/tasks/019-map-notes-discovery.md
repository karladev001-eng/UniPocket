## 目的・根拠

2026-10-20の利用者による実画面4枚と修正依頼。地図の候補が大きく地図が小さい、時間割入口のアイコンが伝わらない、予定詳細で閉じる操作と既知情報が重複する、人気記事を優先したい、記事の検索欄が大きく記事へ到達するのにスクロールが必要、という指摘を受けた。

現状はopenMapで未入力でも全候補を地図より先に表示。時間割入口は文字記号▦。showEventは共通modalの×と閉じるを併用しメモなし。記事は新着順のみで検索・カテゴリ・講義が常時展開される。

## 提案仕様・受入条件

### S1 地図を主役にする（AC1–2）

- AC1: 拡大・検索を開くと、コンパクトな見出し・検索1行の下に地図を表示。空欄の初期状態は候補一覧を出さず、地図は全体表示の1.6倍を初期倍率とする。地図内のドラッグ、ピンチ、＋／−、全体ボタンで移動・拡縮できる。倍率は全体基準1〜4倍。390×700でキーボードを閉じた初期状態の地図領域は高さ400px以上。地図の閉じる操作も右上×一つ。通常画面の操作説明、空欄の説明、常設の出典・精度の文章は表示しない。出典・精度情報はカタログと仕様資料に保持する。検索語があるときだけ検索欄の右端に小さな×を表示し、押すと入力と候補・強調を解除して入力欄へフォーカスを戻す。地図を閉じる×とは位置とアクセシブル名で区別する。
- AC2: 入力したときだけ建物名・別名・登録済み教室の候補を検索直下へ表示。行の見た目を簡潔に、操作高さ44px、最大3行の高さで残りは候補内をスクロール。候補を省略せず到達可能にする。矢印キー・Enterに対応し、Escapeは候補表示中なら候補だけを閉じ、候補が閉じた状態では地図を閉じる。選択後は候補とキーボードを閉じ、選択建物を中央に寄せて強調。空欄・検索0件・複数候補・オンラインを区別し、不明な教室の建物を推測しない。通常の候補件数や選択方法の説明は読み上げ通知に限り、画面には候補と選択建物名だけ。0件は「見つかりません」、オンラインは「オンライン」の短い状態表示だけにする。再検索時は古い強調を解除。全体表示でも選択は保持。ホームの場所→地図へスクロールする既存導線は保持し、拡大で選択を引き継ぐ。

### S2 ホームの導線と時計アイコン（AC3）

- AC3: 「時間割を見る」は文字記号をやめ、文字盤と針が分かる線画SVGの時計アイコン（18〜20px）を使用。ラベルと控えめな大きさ・44pxのタップ領域を維持し、ホームから1回で開く。色だけに依存しない。今日の予定見出し横にある「予定表へ／予定表を見る」ボタンは削除し、予定表への入口は既存の下部「予定表」タブを使う。下部5タブの構成・順番、今日の予定一覧は維持する。

### S3 予定にメモを書く（AC4–6）

- AC4: 詳細は右上×だけで閉じる。長いタイトルと×を別列に置き、×を折り返さない。日時・場所を小さくまとめ、予定編集は補助操作へ。主領域は「この予定のメモ」の複数行入力。場所→地図の既存操作と全文確認は残す。
- AC5: メモはその予定ID（授業ならその回）ごとの個人テキスト、最大5000文字。端末内へ入力停止500ms後に自動保存。状態は保存中／保存済み／保存できませんだけ。保存前の×・Escape・場所移動・予定編集は保存完了を待つ。失敗時は詳細と入力を残し、再試行と入力の書き出しを用意。編集中・保存中・保存失敗時の自動更新を待機させ、別タブ競合では無断上書きしない。本文はプレーンテキストで扱う。
- AC6: ホーム・時間割・予定表の同じIDでは同じメモを開く。タイトルや時刻の個人修正、同じIDのPDF再取込で保持し、別の授業回へコピーしない。予定取消・削除・取込差し替えで参照が無くなってもメモ本文を自動消去せずデータ書き出しに保持。異なるIDへ推測で付け替えない。旧データでは空として読み、通常メモとPDF解析内容は変更しない。メモ欄の全消去が保存されると、その予定のメモを削除できる。

### S4 記事が先に見える（AC7–8）

- AC7: 記事一覧の初期並びを「人気」にする。提案の注目スコアは直近7暦日（日本時間、今日を含む）の閲覧数＋現在のブックマーク数×3。同じユーザーの1日1閲覧という既存集計を維持。同点は作成日時降順、ID降順、全件0点なら新着順。画面には累計閲覧数を目の線画SVG＋数字、現在のブックマーク数をしおりの線画SVG＋数字で表示する。「閲覧」「ブックマーク」の繰り返しラベルは表示しない。閲覧数は非操作、しおり＋数字はブックマーク切替操作とし、選択中は塗りつぶし＋aria-pressedで区別。読み上げ名は意味・数値・操作を含める（例: 閲覧128回／ブックマーク18件、登録する）。「保存／保存済み」の別ボタンは重複表示しない。人気／新着を切り替え可能。検索・カテゴリ・講義・投稿者・ブックマークを適用した全対象にサーバー側で順位を付け、20件取得の後に並べ替えない。新着APIの既存クライアント互換を保ち、新UIからsort=popularを明示する。
- AC8: 「記事」と小さな登録操作、検索1行＋絞り込みボタン、人気／新着／ブックマークのコンパクトな3択切替の直後からカードを表示。ブックマークは自分の保存記事を新着順で表示し、人気・新着へ切り替えたときはブックマーク限定を解除する。検索語・カテゴリ・講義・投稿者の条件はどのタブでも維持する。記事内の通常ボタンは大きな塗りつぶしや囲みを減らし、登録は小さな文字操作、絞り込みはスライダーSVG＋適用数、3択は文字と選択下線で表す。アイコン18〜20px・余白を小さくして見た目を軽くしつつ、操作領域は44px以上で重ねない。検索の入力文字は16px以上を保つ。絞り込みシートの候補も簡潔な行とチェックで示し、ネイティブ選択メニューに戻さない。英字見出しとNotion説明を初期一覧から除く。カテゴリ・講義は絞り込みシートへ移し、適用数と解除を表示。390×700・標準文字サイズで最上位のカード（長い題名・短い紹介文・閲覧/ブックマーク数）が下部タブより上に収まる。1件でも空の人気枠を作らない。絞り込みで0件・全体0件・取得中・失敗／前回取得値を別表示。記事本文、投稿、名前付き投稿者の絞り込みは維持し、匿名の投稿者絞り込みは増やさない。

### S5 回帰と境界（AC9）

- AC9: 320×640/390×700/PC、長い題名、文字拡大、キーボード表示で操作不能やページ横溢れを起こさない。タップ領域44px、フォーカス・Escape・動きを減らす設定を確認。APIの並び・同点・7日境界・50件以上のページ継続・絞り込み・旧クライアントを検証。固定データでは全件に重複欠落なく到達。順位変動中の取得はID重複を除去し、再読み込みで先頭から最新順位を取得する（リアルタイムの完全な順位スナップショットは対象外）。ブックマーク直後に読んでいるカードを勝手に移動させない。PDF、既存予定、通常メモ、背景、自動更新の保護、本人限定Accessを維持。

## 入出力・構成・依存

- 地図入力は検索語・登録カタログ・任意の既存場所。出力は候補と既存画像上の強調位置。新しい位置情報取得や外部地図APIは不要。
- 予定メモはDataへ後方互換の任意eventMemosレコード（eventId→text/modified）を追加する案。IndexedDBの既存永続化・競合処理を共用。クラウド送信・アカウント新設はしない。通常の書き出しに含める。
- 記事ランキングは既存view_events.day_jstとbookmarksを用いてSQLで計算。新規の行動追跡やD1テーブル追加は不要。sortとカーソルの組合せを検証し、不正値は400。集計期間はページ継続中はカーソルに固定し、再取得で更新。順位変動そのものは固定しない。
- 予定詳細と地図に限定して閉じる重複を修正する共通modalオプションを検討。他の入力フォームの確認や保存処理を一律変更しない。
- 段階: 仕様・モック確認→承認範囲の実装→独立レビュー・ローカル検証→本人限定previewの配信判断。仕様・モック提示後に版2の実装承認を受領し、実装まで完了。配信は別判断。
