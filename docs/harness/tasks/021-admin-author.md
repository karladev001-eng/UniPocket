## 目的と根拠

ユーザー: 「管理者として投稿したいです。ユーザー名のところに管理者とわかるようなマークをつけたりできますか。」

管理者が公開Notion記事を運営名義で登録でき、利用者が一般の投稿と見分けられるようにする。現行管理画面は記事の非表示・再公開のみ。一般ユーザーの名前変更は認可ではないため、バッジの根拠にしない。

## 全体像

本人限定の既存管理画面 → 記事 →「＋ 運営記事」→ 登録情報を入力 → 公開表示を確認 → 公開。一般アプリの記事カード・詳細・投稿者で絞った一覧に、小さな盾チェックSVG＋「管理者」を表示する。表示名の提案は固定の **Uni Pocket運営**。メールアドレスは公開しない。

Notionの本文作成・Web公開はこれまでどおりNotion側で行う。先に作成した投稿ガイドは現在非公開の下書きであり、モック中の掲載例は公開済み記事を意味しない。今回の仕様承認は、そのNotionページの公開や実際の記事投稿の承認を兼ねない。

## 提案仕様と受入条件

### S1 小さなバッジで運営記事を識別する（AC1–2）

- **AC1 表示**: 記事カード・詳細・ブックマーク/投稿者で絞った一覧・管理画面の投稿者行で「Uni Pocket運営 ［盾チェック 管理者］」を表示。通常の投稿者行と同じ大きさの名前、短い文字ラベル付きのバッジとし、アイコンだけ・色だけで判定させない。バッジは操作ボタンにしない。運営名から同じ運営記事を絞れる。人気順の加点・上部固定・既存記事の順位変更は行わない。
- **AC2 信頼境界**: バッジは認証済み管理APIから新規作成された記事のサーバー保存属性だけで決定する。公開API・匿名プロフィール・投稿フォームからの権限/著者種別の指定は拒否。同じ表示名を名乗る一般ユーザーにバッジは付かない。バッジは運営の投稿元を示すもので、Notionアカウントの認証や内容の正確性の保証ではない。既存記事は通常投稿のまま保持し、自動で運営記事に変えない。

### S2 管理画面で投稿し、同じ画面で直せる（AC3–5）

- **AC3 投稿**: 既存管理画面「記事」に小さな「＋ 運営記事」を追加。題名120文字・Notion公開HTTPS URLが必須。紹介280文字・カテゴリ60文字・講義ID120文字・公式埋め込みURLは任意で、現行のNotion URL検証・埋め込み入力変換を再利用。投稿者は固定表示で変更不可。入力→プレビュー→「公開する」の確認後に即時公開。一般公開の確認チェックを設け、埋め込み未入力時は元ページでの確認を案内。iframe読込成功を公開状態の保証にしない。下書きは編集中の画面内で保持し、新たな共有下書き・予約投稿機能は作らない。
- **AC4 編集・非表示**: 新規運営記事の登録情報は管理画面からのみ編集でき、公開済み変更もプレビューと反映確認を経る。他人の投稿の著者や内容を書き換える機能は追加しない。既存の非表示・再公開・理由入力を運営記事にも適用。Notion本文はNotionで編集する。公開アプリの匿名セッションには運営記事の編集/削除権限を与えず「自分の投稿」に混ぜない。一般利用者の閲覧・ブックマーク・通報と運営名での絞り込みは従来どおり利用可能。
- **AC5 失敗と入力保護**: 入力不正は該当欄で示す。送信中の連打を抑え、通信失敗・認証期限切れ・離脱では入力を保持し、再認証後に再試行可能。再送で二重投稿を作らない。同じ運営名義の同じ正規化Notion公開URLは重複登録せず、既存記事への案内を返す。別画面で更新された場合はrevision競合を示して上書きせず、現在の入力を保つ。非表示との競合で意図せず再公開しない。

### S3 既存認証とデータを保って追加する（AC6–8）

- **AC6 認可・保存**: 管理画面と管理APIの既存Cloudflare Access＋署名/issuer/audience/期限/所有者検証をすべて維持。各作成/編集リクエストで認可し、Origin検証・レート制限・冪等キー・revision・監査を適用。記事と成功監査は同一D1 batch/transactionで成立させる。作成した運営著者は匿名セッションから取得・更新できない独立IDとして扱い、記事の信頼属性もサーバーが設定。認証メールは内部監査のみで、公開API・DOM・エラーに出さない。入力や認証トークンを監査本文に保存しない。
- **AC7 移行と互換**: D1は追記migrationで運営著者種別を追加（既存記事の初期値は通常）。記事ID・著者権限・閲覧・ブックマーク・人気順・既存プロフィール・端末の予定/メモを保持。公開APIは安全な著者種別だけを追加し、旧クライアントでも記事を読める。新クライアントは種別なし/未知値を通常表示とし、勝手にバッジを付けない。公開側に管理APIを追加しない。
- **AC8 検証と配布**: 320px/390px/PCで長い題名・投稿者名、キーボード/フォーカス、44px操作域、16px入力、単一閉じる操作を確認。認証済み投稿/編集/非表示/再公開、匿名偽装・API直接更新・期限切れ・別audienceの拒否、重複/二重送信/競合/監査失敗時の原子性を検証。既存集計と匿名投稿も回帰確認。実装後に配信内容と検証結果を提示する。今回の新機能の配信・実記事投稿はまだ未承認。
