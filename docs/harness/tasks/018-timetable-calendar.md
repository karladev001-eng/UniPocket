## 目的・根拠

利用者は017配信後「時間割としては今のままで見やすい」と評価し、次の予定を前版のように強調、時間割とカレンダーを分離、時間割はホームから1クリック、予定表はOutlookを参考にする案を希望。続いて「その方向でいいと思います」「まずは外部カレンダーとの連携なしで進めましょう。その方向で仕様とモックを作ってください」と依頼。

同じ講義データを2つの見せ方で使い、コマ表には講義、カレンダーには講義と自由な予定を表示する。重要情報を上に置く017の密度、背景/設定/更新の整理を継承する。

## 対象内外・入力と出力

- 対象: ホーム、時間割、予定表、新規予定/既存編集への導線、下部5タブ、表示用の分類と時間軸レイアウト、場所からホーム地図への移動・該当建物の強調。
- 入力: 保存済みPDF由来の講義/試験/大学行事、手入力の個人予定、個人修正、日付・表示切替・選択。出力: コマ表、時間軸/月表示、共通の詳細/編集、今日/次の予定。
- 外部連携なし: Google/Apple/Outlookとの同期、購読、ICS取込/書出し、外部カレンダー認証を追加しない。Outlookは画面の参考。新規アカウント・クラウド予定同期も追加しない。
- 対象外: PDF解析変更、講義を手入力する新機能、ドラッグ移動/リサイズ、招待/共有、新たな繰返しルール、記事/メモの仕様変更、Swift、013地図再設計。
- 既存の端末データ、PDF取込、編集範囲/取消、保存失敗回復、背景、テーマ、自動更新安全待機、本人限定配布を保持。初回からデータを入れ直さない。

## 提案仕様・受入条件

### S1 ホームと移動（AC1–2）

- AC1: 下部は「ホーム / 予定表 / 記事 / メモ / その他」の5つ。ホーム上部の日付横、スクロール不要の位置に「時間割を見る」。補助操作は13px程度の文字と小さなアイコンを中心にし、幅広の塗り付きボタンにしない。高さ44px以上のタップ領域は維持し、視覚的な大きさと操作のしやすさを両立する。1タップで選択日を今日へ戻して現在週の講義コマ表を開く。時間割には「ホームへ」「予定表へ」の入口を置き、同じ週/日付を引き継ぐ。予定表の補助メニューにも時間割入口を設ける。旧 #timetable のURLは引き続き時間割へ到達可能。
- AC2: 日付と時間割入口→濃いテーマ色/白文字の次の予定カード→今日の予定の順。次の予定は時刻を強く、題名2行/場所を表示。実行中は「いまの予定」として区別し、終わっていない最も早い予定を表示（終日は次回カード対象外、今日一覧には含む）。複数重複時も今日一覧から全件確認できる。次の予定は今日一覧にも残す。
- 390×700 CSS pxで次/いま1件と今日先頭3件の時刻・題名・場所を初期表示。320×640や文字拡大は通常スクロール可能。今日0件/次回が明日/次回なしの状態も用意。更新や正常保存の通知をホームへ戻さない。ホーム地図は固定リンク直上を保持。
- AC2（場所から地図）: 次/いまの予定、今日一覧、共通の予定詳細では場所を独立した操作にする。場所タップは予定詳細を開く操作と分離し、buttonの入れ子を作らない。ホームでは既存のキャンパスマップまでスクロールし、予定表/時間割の詳細からは詳細を閉じてホームへ移動したうえで同じ地図へスクロールする。地図見出しへフォーカスを移し、選択した場所名を表示。動きを減らす設定では即時スクロールにする。
- 場所解決は既存の登録済み教室・建物・別名を使う。一意に一致した建物をマーカーと名称で強調する。教室名が登録済みでも現在の地図データは建物座標のみなので、教室名と「建物の位置」を表示し、教室内の正確な位置を捏造しない。複数候補は選択前にピンを出さず候補選択、未登録は「場所を特定できません」と元の場所を示し、建物検索へ進める。場所未設定・オンラインは地図リンクを付けない。別の場所選択時は以前の強調を消す。
- 地図の配置・基本意匠・既存画像/建物データを維持し、場所導線に必要な強調・結果表示だけを追加する。013の地図全体再設計、外部地図/GPS/経路案内は含めない。

### S2 講義専用の時間割（AC3）

- AC3: 017の月〜金×1〜5コマ、時刻12px、安定した科目色、土日切替/件数、週移動、重複選択を維持。対象はPDFの kind=class/exam とその既存個人修正（preservedEventsを含む）。試験は「試験/要確認」の文字でも区別。個人予定・大学行事はコマへ入れない。
- コマ外/時刻変更/終日化/日またぎの講義は「コマ外の授業・試験」に日時付きで全件残し、カレンダーにも同じ時刻で載せる。取消の扱い・取消管理は既存仕様を維持。空欄は空きコマ、空の週は短い案内。講義未登録時はPDF取込を案内。
- 既存の手入力予定は削除せず、予定表へ全件残す。今回の手入力は個人予定のみ（新たな講義作成機能は追加しない）。時間割の＋予定は予定表の追加フォームへ進み、講義セルを作る操作と混同させない。
- 390×700で5コマが下部ナビより上、320×640で最初の3コマ、平日5列のページ横スクロールなし、科目セル12px以上/操作対象44px以上を維持。

### S3 時間軸の予定表（AC4–5）

- AC4: カレンダーは「日 / 3日 / 週 / 月」切替。初回はスマホ390px相当で3日、狭幅320pxで日、PCで週を提案。利用者が選んだ表示は起動中保持し、勝手に切り替えない。初回の表示は端末幅から選び、リサイズだけでは選択をリセットしない。3日は選択日から連続3日、週は月〜日、前後移動は表示単位（月移動は移動先の1日を基準）、今日ボタンで当日に戻る。
- 縦に時間、横に日付。予定ブロックを実際の開始・終了に対応させ、講義・個人予定・大学行事を一緒に表示。時間目盛は30分、位置は実際の分単位。00:00〜24:00の全時間へ縦スクロールでき、初期スクロールは当日なら現在時刻付近、別日なら最初の予定付近（予定なしは表示開始設定時刻）。早朝/深夜を表示範囲の外へ消さない。現在時刻線は今日の列のみ。
- 小さいスマホで週を選ぶ場合は日列の幅を確保する内部横スクロールを許可し、日/3日を普段使いの推奨とする（時間割の横スクロール禁止とは別）。日付見出しと時刻軸を見失わない構造にする。長い題名は省略し、タップ詳細で全文・実日時・場所を表示。
- AC5: 同時刻は横並び。密集して狭すぎる場合は「この時間にN件」から全件一覧へ進み、件数だけで予定が失われない。短時間予定も44px以上の詳細入口を確保し、拡大した入口が実時間と誤認されないよう時刻を明記。終日は上の独立帯、複数日終日は各対象日、日またぎは境界で分けて続き表示し、詳細は同じ元予定を開く。時間範囲は開始を含み終了を含まない（00:00終了は翌日に余分に出さない）。Tokyo基準を統一。
- 月表示は全日へ到達できる月グリッド、日付ごと件数と短い予定。日付選択でその日の時間軸へ、密集日は件数から全件確認。空の日、予定重複、終日、日またぎ、講義時間変更、文字拡大をモック/実装検証に含める。

### S4 共通データと操作（AC6–7）

- AC6: `events(data)`の既存編集適用済み予定を一度基準にし、時間割はkind=class/examで絞り、予定表/ホームは全件を利用。表示のための予定コピーを保存しない。同一idを使い、講義の時刻/場所/取消変更は双方とホームに反映。未知のkindやcourseIDが失われたpreserved予定も予定表から落とさない。色は科目の見分け補助を継承し、種類は文字/アイコンでも示す。
- AC7: 予定タップで共通詳細/既存の個人修正へ。予定表の＋から個人予定を追加し、選択日を初期値にする。空の時間枠タップもその日時で追加へ進める。保存/閉じる、取込プレビュー/個人修正競合、編集中自動更新待機、保存失敗の再試行/入力書き出しは保持。日付移動や表示切替だけでは保存データを変更しない。色変更・ドラッグ移動など未承認機能をモックの本操作に見せない。

### S5 保持と検証（AC8）

- AC8: 390×700/320×640/PCでホーム、時間割、日/3日/週/月、詳細/追加を確認。授業/個人予定の分離、同一予定の編集反映、3件以上重複、5分予定、終日、日またぎ/週境界、空、長題名、保存失敗を検証。時間割入口の控えめな外観と44pxタップ領域、場所タップによるホーム地図への移動・対応建物の強調、未登録/複数候補/オンライン/空欄、別場所選択時の旧ピン消去、キーボードフォーカスとreduced-motionを確認。既存PDF/背景/メモ/記事/更新待機の回帰、自動テスト、独立レビュー後に実装段階で配信する。
