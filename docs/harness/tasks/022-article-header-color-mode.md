## 目的と依頼

「自分の投稿と+登録のボタンの場所が違和感があります。また、ライトテーマとダークテーマを切り替えられるようにしてください」

追加の依頼: 「記事を読むまでの項目が長いです。通報、再読み込み、Notionで開くであまり説明はいらないと思います。閲覧やブックマークの説明も不要です」

添付の実画面では記事見出しの下に操作が別行で置かれ、リンクとボタンの高さも揃っていない。現在のモバイルCSSは`.heading .row`を幅100%にしており、記事画面も折り返される。現在の`theme()`はgreen/blue/rose/monoの色を変更する機能で、明暗の区別はない。白い背景や入力欄を固定色で持つ部分もあるため、背景だけの変更ではなく一般アプリ全体の配色を整える。

## 全体像

記事画面は左に「記事」、右に「自分の投稿」と「＋ 登録」を一列で揃える。小さな操作を右側へまとめ、すぐ下に検索・並び替え・記事を表示する。既存の投稿・検索・絞り込み・人気順の動作を保つ。

記事詳細はタイトル・紹介・投稿者/管理者バッジ・閲覧/ブックマークの数字をコンパクトに表示し、「通報 / 再読み込み / Notionで開く」を小さな操作行にまとめ、その直下に本文を置く。通常時の閲覧/保存の定義、通信・公開状態の説明、「記事のメニュー」の見出し、大きな説明ボックスを外す。異常時だけ必要な短い案内を出す。

「その他 → 背景・テーマ」の先頭に **ライト / ダーク** の2択を追加する。初期値はライト。現在の色の選択は「カラー」として残し、背景画像もそのまま使用できる。選んだ明るさはこの端末に保存し、再起動後も使う。管理画面は今回の対象外。

## 提案仕様と受入条件

### S1 記事の操作を見出しの右に揃える（AC1–2）

- **AC1 配置**: 記事一覧のヘッダーは左に「記事」、右側に「自分の投稿」「＋ 登録」を同じ中心線で表示。自分の投稿は控えめな文字リンク、登録は小さな枠付きボタン。見た目を大きくせず、いずれも44px以上の操作域を保つ。320pxでも見出しの下へ操作だけが折り返されず、横スクロール・重なり・省略なし。大きな英語副題・補助説明・固定のフローティングボタンは追加しない。
- **AC2 動作と密度**: 自分の投稿は既存の作者専用一覧へ、登録は既存のNotion登録フォームへ進む。検索欄・絞り込み・人気/新着/ブックマークは直下に配置し、一覧の先頭を押し下げる余白を減らす。検索条件・並び・閲覧/ブックマーク・運営バッジ・作者権限を保持。記事詳細への変更はAC9–10の範囲とし、他画面のヘッダーへ不用意に共通CSS変更を波及させない。

### S2 ライトとダークを明示して選ぶ（AC3–4）

- **AC3 選択**: その他の「背景・テーマ」を開くと、先頭に「明るさ：ライト / ダーク」の選択を表示。ラベル付きの小さな2択で、選択状態を色とチェック/形の両方で示し、キーボードで選べる。初期・旧データはライト。選択は画面へ即時反映し、既存の端末内保存を使う。OS連動や自動時間切り替えは追加しない。
- **AC4 独立した設定**: 明るさの下に現在の4色を「カラー」として残す。グリーン/ブルー/ローズ/モノトーンをライト/ダークでそれぞれ読める配色にする。背景なし・サンプル6種・自分の画像を保持し、明暗変更で画像を解除/置換しない。画像の前の下地やカードの不透明度を明暗に合わせ、背景上でも本文を読めるようにする。「背景・テーマ」の閉じた行に現在の明暗を短く示す。通常画面にテーマ説明や専用の大きなバナーを追加しない。

### S3 一般アプリ全体の表面と文字を合わせる（AC5–6）

- **AC5 対象**: 一般アプリのホーム・予定表・時間割・記事一覧/詳細・自分の投稿・メモ・その他・お知らせ/アンケートと、各入力/選択/確認ダイアログを対象にする。本文/補助文字、カード、入力、選択肢、区切り線、固定ヘッダー/下部タブ、安全領域、地図の操作枠、ポップアップ、通知/エラー/無効状態、管理者バッジまで明暗を統一。色の意味を保ち、リンク・フォーカス・選択中・エラーを判別できる。通常文字は背景に対して4.5:1以上を目安に検証し、強い装飾や単純な画面反転で対応しない。
- **AC6 元のコンテンツと初期描画**: 背景画像・地図画像・PDFの内容・メモの色分類・講義色の意味は維持する。Notion埋め込み内部とリンク先サイトの配色は相手側に従い、強制反転しない。Web側のcolor-schemeとテーマ色も選択に合わせる。保存済み明るさを再起動時に反映し、ダーク選択後の起動でライトが長く残るちらつきを抑える。OS固有のステータスバーの見え方は対応ブラウザの範囲で扱い、Web画面の検証と区別する。

### S4 設定だけを保存し、既存の内容を守る（AC7–8）

- **AC7 保存・互換**: 既存Dataの色キーを保持し、追加の明暗設定は未保存ならライトとして読む。旧IndexedDB/書き出しファイルが明暗設定を持たなくても読める。新しい設定も書き出しに含める。未対応・壊れたデータは現行の保護手順で扱い、端末データを初期化しない。保存失敗は入力を残して再試行を示し、保存できたように扱わない。画面の明暗変更で予定・メモ・背景・PDF取込・記事の下書きや匿名セッションを消さない。共有DB変更・設定のサーバー送信は不要。
- **AC8 検証**: 320×640/390×700/PCで両明暗の見出し・検索/最初の記事・設定・ダイアログ・下部ナビを確認。4色×2明暗、背景なし/サンプル/自分の画像、長い題名、空/読込/エラー/無効/フォーカス、44px操作域・16px入力を検証する。旧データの読込・設定保存/再起動・書き出し・失敗時保持を意味あるテストで確認し、既存投稿/人気/ブックマーク・予定/メモの回帰チェックを行う。実装後の配信は別途確認する。

### S5 記事の説明を減らし、本文を早く表示する（AC9–10）

- **AC9 通常表示**: 詳細の英語副題NOTION ARTICLEと、閲覧回数/ブックマークの定義、Notionの通信や公開確認・読込イベントの技術説明を通常画面から外す。タイトル・紹介文・カテゴリ・投稿者・管理者バッジ・アイコンと件数を残し、大きな余白や外側のカードを減らす。紹介文は投稿者が入力した内容として表示を保つ。投稿者/数字はコンパクトな行で、長い名前は自然に折り返す。「記事のメニュー」の開閉見出しをなくし、**通報 / 再読み込み / Notionで開く** を小さな同じ操作行に置き、そのすぐ下にiframe本文を配置。通常の説明ボックスは置かない。44pxの操作域・リンク/ボタンのラベルを保ち、補足の読み上げラベルは削除しない。今回の添付程度の題名/紹介なら390×700の初期表示に本文の先頭が入ることを目標に実画面で検証し、長文や外部Notionのヘッダーの高さを無条件には保証しない。
- **AC10 動作と異常時**: 通報は既存の理由入力と送信フロー、再読み込みは既存の公開状態再確認を経る処理、Notionで開くは既存の安全な外部リンクを使う。埋め込み未登録時は「埋め込み未登録」程度の短い状態と元ページの入口を表示し、意味のない再読み込みは出さない。オフライン/取得失敗/非表示・削除時は必要な短い状態と再試行/一覧の入口だけを出す。iframeを挿入する前の公開API確認、URL検証・sandbox・referrer制約を維持し、非表示記事を読ませる経路を増やさない。閲覧記録の失敗でも本文表示を妨げず、未成功の増分を表示へ加算しない。ブックマーク/通報の失敗は短く示し、成功したように扱わない。本人だけの編集/削除は補助メニューへまとめ、削除確認と権限を保持。Notion自体のヘッダー/メニューは外部ページの表示として扱い、取り除く機能は作らない。両明暗・狭幅で本文開始位置と通常/未登録/オフライン/失敗/作者本人の状態を検証する。
