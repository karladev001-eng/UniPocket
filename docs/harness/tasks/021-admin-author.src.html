UNI POCKET · PLAN 021 / v1 · 実装承認待ち

運営からの記事だと、ひと目でわかる。

目的と依頼管理者として投稿したいです。ユーザー名のところに管理者とわかるようなマークをつけたりできますか。

管理画面から投稿すると、名前の隣に管理者マーク。

投稿者名は Uni Pocket運営。小さな盾チェックと「管理者」を添えます。名前を同じに変えた一般ユーザーには付きません。

本人限定の管理画面 → 記事 → ＋ 運営記事 → 入力・プレビュー → 公開。一般の記事と同じ一覧・詳細で読めます。人気順を優遇する変更はありません。

今回の提案は管理者の投稿・編集とバッジ表示。既存認証と共通DBを使います。実装後に認可・二重投稿・既存データを検証し、配信と実記事の登録は別途確認します。

下のモックはすべて提案です。先ほどの投稿ガイドはまだNotionの非公開下書きです。仕様正本: 021 / v1。

提案仕様とモック

記事の投稿者行に、小さく「管理者」を添える。（AC1–2）

名前ではなく、サーバーに保存した運営記事の種別で付ける。

詳細にも同じバッジを表示し、運営名から他の運営記事を探せる。

現在はプロフィール名を表示しており、運営の種別を追加する。

管理画面の「記事」から運営名義で投稿できる。（AC3–4）

プレビューで公開先と名義を確認してから、公開する。

運営記事だけを編集でき、非表示・再公開は既存操作を使う。

失敗しても入力を残し、重複や上書きを防ぐ。（AC5）

送信中

「公開しています…」と操作を無効化。完了後は登録した記事へ。

通信失敗 / 認証期限切れ

入力を保持し、再試行または再ログインを案内。自動リロードで消さない。

同じURL / 更新の競合

既存記事または最新情報への確認操作を示す。二重投稿や上書きはしない。

入力を残したまま、必要な復帰操作を表示する。

本人確認とDBの属性を根拠にし、匿名ユーザーから偽装できなくする。（AC6–8）

運営著者を匿名セッションから分離し、既存記事には通常の種別を補う。

一般投稿の任意フィールド拒否を維持し、種別の指定を受け付けない。

一般ユーザーのログインや人気順位の優遇、既存投稿の著者変更は含めない。

  • 一般アプリからの管理者切替・複数管理者の権限管理は対象外。
  • Notionページの公開、実際の記事投稿、Cloudflare配信は別途確認。

受入条件

  1. AC1: 一覧・詳細・関連一覧・管理画面の投稿者行に文字付きの小さなバッジを表示。
  2. AC2: 通常ユーザーの同名や偽装入力ではバッジが付かない。
  3. AC3: 管理画面の入力→プレビュー→確認で運営記事を公開。
  4. AC4: 運営記事の編集・非表示・再公開と通常投稿の権限を分離。
  5. AC5: 認証・通信失敗・重複・競合で入力と記事の整合性を保持。
  6. AC6: 既存認証を毎回検証し、監査と記事更新を原子的に保存。
  7. AC7: 追記migrationと旧版互換で既存記事・件数・投稿者権限を保持。
  8. AC8: 320/390px・PC、認可・競合・回帰を検証し、配布は別途確認。

制限や長さの詳細・異常時の契約は仕様正本を参照。
