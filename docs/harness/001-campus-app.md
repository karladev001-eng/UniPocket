- 週ヘッダ・切替・残り時間・凡例・選択カード・タブの高さを固定し、残りを週のグリッドに割り当てる。文字を一律縮小して詰め込まない。大きな文字では読みやすい日別一覧・詳細を使い、全情報の固定1画面表示は保証しない。
- 短い予定は正しい時間位置のマーカー、重複は件数で示し、日をタップして全件一覧へ。終日・範囲外は日付別件数を集約し、日表示で確認できる。対象があるのに「なし」としない。表示範囲は設定で変更できるが、全24時間への自動拡張で授業枠を潰さない。
- 現在線は今日の列だけ、日表示も今日だけ。毎分・フォアグラウンド復帰・日付変更時に更新。別日や別週に現在線を置かない。見える時刻範囲外なら現在時刻の案内から今日へ戻れる。
- 月表示は選択日の一覧に開始・終了を併記し、今日を選んだ時だけ残り時間を出す。モックの日一覧は文字拡大時の代替案。通常の日表示は週と同じ連続時刻軸。
- 授業/外部予定/行事/試験候補をラベルと色で区別。予定が重なる場合は並列または一覧に展開し全件にアクセス可能とする。件名一致だけで予定を消さない。
- 営業時間は授業の文字を遮らない淡い帯。表示する食堂/ショップと表示ON/OFFを選ぶ。初期案は南館食堂・北館ショップ。凡例を下部1行に集約。施設名、開始終了、確認日、例外は帯をタップした詳細に文字で表示。
- 施設の日付例外を通常曜日より優先。昼夜を別帯にし、間の閉店時間を塗らない。休業なら帯なし・休業ラベル、未確認は通常期の目安。色覚・ダーク・VoiceOverでも識別できるようにする。
- ホームに画像カードを配置し、タップで拡大。位置は次の授業・営業時間・ショートカットの下。Q7の回答に従い固定メモの先頭画像、タイトル、並び順を使う。固定がない時はカードを表示しない。

### S2 提示済み後期PDF・授業の修正

- Filesから履修登録票と行事予定表を選択し端末内解析。年度/学期/ページ/表位置を検証。個人情報は保存しない。確認後に取り込む。
- 通常科目4、日時未定2、56通常授業＋4試験候補という既知例を受入基準にする。11/25の月曜授業、11/6浜松休講、1/7、年越し、夜間主コース除外を維持。試験候補を確定予定と混同しない。
- 個別休講・日時・教室・表示名の修正、科目全体への変更、日時未定の研究/セミナーへの日程追加を提供。操作前に適用範囲を表示し元に戻せる。休講は取消し情報として保持。
- PDF原本由来データと個人修正を分ける。同一PDFで増殖しない。再取込は追加/変更/削除候補を確認。個人修正との衝突は選択して解決し、失敗や取消しでは保存済みを維持。
- 初回対象は提示済み後期形式。前期・未知形式・画像PDF/OCRは対応済みとしない。PDF授業はアプリ内のみに保存。

### S3 Outlookは表示のみ

- iPhone標準カレンダーで利用できるOutlook/Exchange予定をEventKit経由で読み、選択したカレンダーを週/月/日/ホームで表示。Outlookアプリのみのログインを接続済みとみなさない。
- OSの読み取りに必要なアクセス許可と、アプリの機能を区別。OSの許可名称が書き込みを含んでも、アプリ側は外部予定の追加・変更・削除を行わない。
- 初期版の書出しUIと呼出し経路を外す。PDFの再取込・個人修正はOutlookへ反映しない。過去に外部へ書き出した予定の削除・変更も行わない。
- 旧書出しの所有マーカー・管理IDが正確に対応する場合だけ重複表示を抑止。単なる件名/時刻一致では隠さない。
- 許可拒否/取消し/対象なし/取得できない範囲を「予定なし」と混同しない。権限取消し時は外部予定を非表示とし、メモや授業などは利用可能。
- オフラインでは端末から取得可能な予定を表示し、端末取得日時と最新同期が未確認であることを示す。アプリ独自の永続的なOutlook予定複製は初回に増やさない。
- 標準カレンダーの実利用可否はユーザー端末で未確認（U1）。直接Microsoft接続や背景同期を暗黙に追加せず、不可と判明した場合だけ連携方式を再相談する。

### S4 施設時間は保存＋手動例外

- 通常期の曜日別区間、昼夜、L.O.、確認日、出典リンクを保存。初期の営業時間例は2026-10-07確認時点で、今回最新確認したとは扱わない。
- 自分で日付別の臨時時間・休業を登録し「個人設定」と表示。通常時間と例外を分けて編集し、例外を解除すると通常時間へ戻る。時刻の前後・区間重複を検証する。
- ホーム/施設/時間割の帯は同じ計算結果から表示。未確認は確定営業中と断言しない。公式案内リンクは提供するが自動取得・解析・差分更新は初回に含めない。

### S5 画像付きメモ・リンク・端末保存

- 「すぐメモ」で本文編集へ1操作。本文はプレーンテキスト、自動保存・検索・更新順一覧。画像だけのメモも作成できる案。画像未添付でも本文は利用可能。
- 画像は写真選択または画像ファイル選択からアプリ内へコピーし端末に保存。JPEG/PNG/HEICの静止画を対象案とし、未対応は理由を表示する。写真全体の収集や自動アップロードは行わない。元の写真ライブラリは変更しない。
- 1メモに複数添付、順序変更・削除が可能。表示は縦横比を保つサムネイル、タップで全体・ピンチ拡大/移動。地図の文字を保つため黙って低解像度化せず、読込上限と必要な縮小は実装時の端末資源確認に基づき理由を表示する。
- 保存中/保存済み/失敗を分ける。クラウドにしかない画像は取得に通信が必要な場合がある。失敗時は本文と既存画像を保ち、再試行または追加取消し。保存済み画像は元ファイルへの一時アクセスに依存しない。
- Q7回答済み：画像付きメモをホームへ固定。先頭画像をカードに使い、並べ替え・固定解除。固定解除は原本を消さない。画像だけのメモも固定可能。メモ削除時に固定参照を解消、画像削除を確認し削除取消し可能な期間はファイルを保持。
- リンクは追加/編集/削除/並べ替え/お気に入り。Web先は通信が必要。保存画像と外部URLを区別し、認証情報を保存しない。
- Q6に従い端末内保存のみ。アプリ独自のバックアップ/復元・iCloud同期は初回対象外。UIの細部はこの版の提案で、実装承認と共に確認する。
